# Identity Reality Check implementation plan

1. Preserve the four acts, strict scoring, typed signals, adaptive investigator and existing export paths. Add a small optional post-verdict interaction, with multi-select, none, decline and bounded unsupported text.
2. Compare self-report against the descriptive Act III result, retaining uncertainty and separating model sensitivity, self-report and untested identity transfer. Skip/decline never become disagreement.
3. Keep identity answers in tab memory. Current hosting is an in-memory Python prototype without research storage, access control or deletion service: use explicit consent, a strict minimal versioned record, review and voluntary download. No collection endpoint or automatic transmission.
4. Add a separate unchecked share permission for identity content in text and PNG. Reset all optional state on new rounds and invalidate consent/preview when answers change.
5. Test classifications, schema, privacy boundaries, original gameplay, exports and desktop/mobile browser flows. Document sampling limits, hosting/terms review, commercial pilot and three business hypotheses without building enterprise features.

Review basis: static/app.js and logic.js, investigator.py and model metadata, server.py memory retention, README, deployment docs, activity coverage and archived controlled partnership study. Public API terms are being rechecked; account-specific negotiated rights are unavailable. No changes to backend scoring or provider calls are planned.
