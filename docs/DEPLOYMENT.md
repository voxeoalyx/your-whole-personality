# Deployment options and local Sites migration

An owner-private Site is deployed at https://your-whole-personality.a-lyx.chatgpt.site. GitHub remains private. See [hosted verification](HOSTED_VERIFICATION.md), [Sites setup](../sites/README.md) and [migration verification](SITES_MIGRATION.md). It uses Vinext/Workers and temporary D1 state, retaining external Qloo/NVIDIA calls. Owner-browser/export checks are pending; this is not public-submission readiness. The following Python hosting instructions describe the preserved reference implementation, not the Sites artifact. GitHub Pages cannot execute either backend.

Use a Python-capable host with an HTTPS reverse proxy. Deploy the root Python files plus `static/` and `data/`; no pip or npm build/install is required. Research and tests can stay in Git without being included in a runtime image. Configure `QLOO_API_KEY`, `NVIDIA_API_KEY`, `QLOO_BASE_URL`, `QLOO_CALL_LIMIT`, `NVIDIA_MODEL` and `NVIDIA_CALL_LIMIT` through the host's secret/environment settings. Never upload a local `.env` as a public asset.

Start with Python 3.10+:

```sh
python3 server.py --host 0.0.0.0 --port 8765 --public-origin https://your-actual-host.example
```

Replace the example origin with the exact real HTTPS origin, without a trailing slash/path, and choose the port required by your host. The proxy must preserve that Host header, terminate TLS, and enforce body-size, request-timeout, rate and concurrency limits. Expose only the proxy. Smoke-check `/`, `/api/config`, and a recorded round before spending live requests. Config exposes capability flags, not keys. One small live round verifies the provider credentials and current availability.

This is a bounded development/hackathon prototype, not a production-hardened server. Run one process/instance: jobs, investigator state, cache and budgets are in memory. Restarts lose sessions and reset budgets; multiple instances would not share them. Two background tasks may run at once, with no unbounded executor queue. Admission and session capacity checks are atomic; live sessions have a 24-record allowance separate from 24 evictable recorded examples. In-process connection-address limits cover search, validation, starts and answers, with a global 120-request/minute ceiling and a conservative 120-unit/15-minute visitor budget (search 3, validation 8, live admission 42; answers are covered by admission). Separate route limits also apply; 429 responses include Retry-After. Raw addresses and forwarding headers are not stored; salted hashes/counters expire after 15 minutes. These limits renew, while the provider process call ceilings remain hard lifetime stops. Restarts reset both. Behind a proxy all requests may share one connection address: enforce trusted visitor identity and shared budgets at the hosting boundary. These protections are single-process and do not replace distributed limits, TLS, or production serving controls. Background work has a cooperative 180-second deadline checked at provider boundaries; a blocking call can finish after it. Review the stdlib server before opening it broadly. Provider free development access is not an unlimited public-service allowance.

Confirm Qloo's applicable display/caching/distribution rights and image requirements before public use. Keep provider privacy disclosure visible. Test real Safari/mobile sharing and failure paths; automatic downloads/clipboard delivery remain unverified on those devices. Use [INVESTIGATOR_RESULTS.md](../INVESTIGATOR_RESULTS.md) for the current evidence and human-evaluation limitations.

The verified model default is `nvidia/nemotron-3.5-super-vl-120b-a12b`; availability remains account-dependent. Prediction fallback and closing-only fallback have distinct player/card labels. Browser requests time out after 20 seconds; retrying a round reuses its job/answer identity. Leaving a screen does not cancel upstream work already running.
